# 장날 버스 지킴표 웹 시연 · 5차

`index.html`을 직접 열면 시작합니다. 서버, 빌드, 외부 CDN이 필요하지 않습니다. `fonts/`와 `data/`를 포함해 폴더 전체를 보관해 주세요. GitHub Pages에는 `poc/web/` 전체를 올리면 됩니다.

## 6개 장면

| 주소 | 사용자 | 눌러 볼 흐름 |
|---|---|---|
| `#scene-1` | 서귀포 상인회장 | 서귀포 선택 → 첫 사용 안내 → 880-1 시장 안 승차 304.8명 / 5.9명 → 공백 후보 근거 → 점검표 |
| `#scene-2` | 한림 동명리 이장 | 미리 입력된 질문 검색 → 모델 해석과 실측 시간 → 한림 선택 → 783번 수치와 공식 시간표 원문 |
| `#scene-3` | 애월 주민 가족 | 제주시 선택 → 마을에서 타는 손님 → 애월읍 증가 → 관찰표 |
| `#scene-4` | 소형 노선 문의 주민 | 고성 선택 → 721 → 구분 안 됨 → 전체 약 20일 필요, 현재 19일 |
| `#scene-5` | 현장 관찰을 마친 이장 | 11/4 장날과 다른 날의 같은 시간대 인원 입력 → 다시 계산 → 의견서 |
| `#scene-6` | 센터 담당자 | 재현 확인 → 기대값과 계산값 → AI 모델 시험 12개 질문 → 주민 관찰 확인 완료 |

시연 띠의 다음 버튼과 주소 해시로 이동합니다. 새로고침과 브라우저 뒤로가기에서도 해당 장면을 엽니다. 실제 서비스 화면에서는 시장, 관찰 기록, 센터 관리 메뉴를 언제든 사용할 수 있습니다.

첫 실행은 개인정보 없이 이용하는 방법을 안내합니다. 계정, 위치, 알림 권한은 요청하지 않습니다. 관찰 저장에는 별도 동의가 필요합니다. 기록은 브라우저에 최대 30일 보관하며, 기한이 지나면 다음 실행 때 지웁니다. 공용 PC에서 지우기, 삭제 되돌리기, CSV 내보내기가 가능합니다. 센터에 보낸 기록은 센터 담당자가 별도 관리합니다.

## 데이터와 근거

숫자는 `python3 agent/run.py --export poc/web/data`의 결과와 동일한 Agent 계산 도구에서 생성합니다. 임의 승차 통계는 넣지 않았습니다. 지도는 오일장 위치를 설명하는 직접 그린 안내 그림입니다.

- 880-1 **시장 안 정류장**은 전체 시장 정류장 합계와 다릅니다. 카드에는 304.8명 / 5.9명, 기간을 바꾸면 128.4명 / 2.3명을 씁니다.
- 길가 정류소 0001914는 별도 접기 영역에서 표시합니다. 2020년 값은 447.6명 / 19.8명입니다.
- 783번의 9.2명 / 0.0명은 2018-07-01~2018-09-30 계산값입니다. 원문 경유 문구는 `agent/data/timetable/x_405085.txt`에서 가져왔습니다.
- 애월읍 증가량은 이번 Agent 내보내기의 실제 `village_lift` 값인 **651.6명/일(2018), 294.0명/일(2020)**입니다. PLAN의 이전 요약치 620명, 265명으로 덮어쓰지 않았습니다. 시장행 승객을 직접 추적한 값이 아니라는 한계를 함께 표시합니다.
- 721번은 서버 판정 이유를 그대로 표시합니다. 필요한 **전체** 장날 자료는 2018년 여름 약 20일(현재 19일), 2020년 봄 약 21일(현재 8일)입니다. 추가 관찰 횟수로 바꾸거나 판정 변경을 보장하지 않습니다.
- 연습 기록은 센터 전송에서 제외하고 “시연용 입력 예시는 센터로 보내지 않아요.”라고 안내합니다. 실제 기록에만 `practice:false`를 붙입니다. 혼합 목록, 오프라인, 실패 후 재시도, 중복 클릭을 검증했습니다.
- 주민 입력은 옛 통계에 합산하지 않고 별도 집계하며 의견서에 붙입니다. 실제 관찰값을 입력할 때는 장날과 다른 날의 같은 시간대를 비교합니다.
- 하단에는 실제 승차 기록과 시간표의 출처·기준일을 표시합니다. 장면 5의 ‘시연용 입력 예시’ 선택은 기록 목록, 의견서와 CSV에 유지됩니다. 실제 관찰값을 적을 때는 선택을 해제합니다.
- 목록은 갈래를 합친 노선 번호와 반올림한 하루 평균을 표시합니다. 880번 전체 시장 정류장은 장날 313명, 다른 날 6명입니다. 2020년 봄의 530번은 파랑 ‘확인 필요’이며 상세에서 비슷한 현재 531번을 확인합니다.

## 파일

- `index.html`, `style.css`, `app.js`: 모바일 서비스, 데스크톱 휴대폰 프레임과 장면 설명, 6개 장면 및 상호작용.
- `data.js`: 파일로 열 때 사용하는 오프라인 묶음. 원시 객체는 화면에 출력하지 않습니다.
- `data/`: 10개 시장·기간 결과 JSON, 30개 A4 인쇄 HTML, 전체 묶음과 재현 검사 기록.
- `fonts/PretendardVariable.woff2`, `fonts/OFL.txt`: 로컬 폰트와 라이선스.
- `prepare.py`: 자료 묶기 및 `agent/web/` 동기화.
- `shot.mjs`: 390×844, 1280×800의 장면별 캡처와 가로 넘침 검사.
- `verify-dom.cjs`: 화면 선택, 입력, 저장, 인쇄 서식, 관리자 연동 등 DOM 기능 검사.
- `test-sync.cjs`: 연습 기록 전송 차단과 실제 기록 전송의 회귀 검사. 대체 응답을 사용하므로 센터에 시험 기록이 저장되지 않습니다.
- `LICENSES.md`: 데이터와 외부 자산 출처.

`agent/web/`에 같은 화면과 자산을 복사했습니다. 로컬 API가 있으면 실행 결과와 문서를 요청하며, 연결이 끊기면 저장된 자료를 사용합니다. 파일로 연 경우에는 요청 없이 묶음에서 읽습니다. 정적 화면의 재현 확인은 저장된 결과이며, 센터 화면은 `/api/check`에서 실제 Python 검사를 다시 실행합니다.

이번 5차에서는 Agent의 판정 코드를 바꾸지 않았습니다. 4차 웹 폴더를 `poc/web-old/`로 옮겼고 이전 보관본은 `poc/web-old-round3/`에 남겼습니다. 피드백 지시대로 기존 시각 구성과 검증된 기능을 재사용해 새 `poc/web/`를 구성했습니다. `docs/spec-demo.md`, `PLAN.md`, `CONTEST.md`, 4차 피드백과 기획서 PDF 추출문을 읽었습니다.

## 5차 모델 실측 기록

`prepare.py`는 `agent/out/llm-bench.json` 원문 전체를 `bundle.json`과 `data.js`의 `llmBench`에 그대로 담습니다. 모델 이름, 측정 기기와 시각, 그래픽 처리 계층 수, 요청별 시간, 계획의 채택·제외 내역을 보존합니다.

- 한림 질문은 원문의 “한림 장날에 783번 없어지면 어떡해요?”로 시작합니다. 검색하면 시장, 노선, 기간, 저장 요청을 한국어 항목으로 표시합니다. 전체 처리 시간 31.3초와 질문 이해 시간 9.9초는 서로 구분합니다.
- 이 질문의 요약과 답변 기록은 전체 8개 중 2개가 검사에 통과했습니다. 근거 없는 숫자 2개, 근거 숫자·판정 없음 1개, 뜻이 서지 않는 짧은 조각 3개를 제외했습니다. 측정 때만 모델 문장을 켰으며 실제 화면은 규칙 문장입니다. 측정 기록의 사용 수를 실제 화면에서 사용한 수로 표시하지 않습니다.
- 센터 시험표는 질문별 4개 판정값을 합산합니다. 이번 기록은 48칸 중 47칸 일치입니다. 측정용 문장 표는 전체 55개 중 검사 통과 21개를 표시하고, 제외 사유는 기록의 문자열 그대로 씁니다. 근거 없는 숫자로 제외한 7개 문장도 코드로 셉니다. 12개 질문 원문과 O/X, 전체 처리 시간을 모두 표시합니다.
- 공개 화면의 질문 해석은 저장된 실측 기록입니다. 로컬 API 결과는 응답의 `llm_log`와 `answer`를 표시하며 과거 기록을 섞지 않습니다. 정적 승차 결과 화면의 문구는 규칙 기반이고, 의견서는 공문이므로 고정 문안을 사용합니다. 원본 인쇄 서식의 생성 출처는 Agent export에 기록된 대로 보존합니다. 기본 실행의 문장 기록에 “기본으로 끔”이 있으면 규칙 문장 안내 한 줄만 표시합니다. 0개 중 0개 같은 집계는 표시하지 않습니다.
- 기간을 직접 바꾸면 이전 질문의 기간 해석이 새 선택을 덮지 않습니다. API 실패는 다시 검색하도록 안내하며, 늦은 응답이 다른 장면을 덮지 않습니다.
- 실측 파일은 개발 PC 측정입니다. 센터 PC 측정으로 표시하지 않으며, 모델을 끄더라도 노선 판정은 같은 계산 도구로 냅니다.

## 갱신과 확인

```sh
python3 poc/web/prepare.py --refresh
python3 agent/run.py
```

센터 주소는 `http://127.0.0.1:8787`입니다. API가 연결된 같은 브라우저에서는 관찰 기록을 ‘센터에 보내기’로 저장할 수 있습니다. 정적 화면이나 연결 끊김 상태에서는 기기에 보관하며 CSV와 의견서로 내보냅니다.

```sh
node --check poc/web/app.js
node --check poc/web/shot.mjs
python3 -m unittest discover -s agent/tests -v
PW_ROOT=/설치경로/node_modules node poc/web/shot.mjs
```

`PW_ROOT`는 `createRequire(PW_ROOT + '/')('playwright')`로 모듈을 읽을 수 있는 경로입니다. 뷰포트 캡처는 `_codex/shots/demo-<장면>-<폭>.png`에 저장합니다. 긴 화면은 고정 띠를 일반 흐름으로 바꿔 `demo-<장면>-<폭>-full.png`에 따로 저장합니다. 모달은 뷰포트만 촬영합니다. 첫 장면 결과, 봄 자료, 530번 상세와 인쇄 미리보기도 추가로 캡처합니다. `DEMO_URL`로 검증할 서버 주소를 지정할 수도 있습니다.

DOM 검사는 별도 검증 환경의 jsdom을 사용합니다. 제품을 실행하는 데는 필요 없습니다.

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory poc/web
DOM_ROOT=/jsdom을_설치한_디렉터리 node poc/web/verify-dom.cjs
```

2026-10-28 검증 결과: 화면 기능 45개, 모델 기록·API 응답 분기 55개, 전송 회귀 6개가 통과했습니다. DOM 검사는 레이아웃 렌더링 검사를 대신하지 않습니다.

```sh
DOM_ROOT=/jsdom을_설치한_디렉터리 node poc/web/verify-dom.cjs
DOM_ROOT=/jsdom을_설치한_디렉터리 node poc/web/test-model.cjs
DOM_ROOT=/jsdom을_설치한_디렉터리 node poc/web/test-sync.cjs
PW_ROOT=/설치경로/node_modules node poc/web/test-web.mjs
PW_ROOT=/설치경로/node_modules node poc/web/shot.mjs
```

`verify-dom.cjs`는 서버 주소를 지정하지 않으면 파일을 메모리 DOM에 읽어 검사합니다. `test-model.cjs`는 실측 원문 전체 일치, 한림 질문 카드, 12행 표, API 답변·오류·늦은 응답을 검증합니다. `test-web.mjs`에는 390px·1280px에서 같은 내용과 가로 스크롤, 해시 뒤로가기·새로고침 검사를 넣었습니다.

2026-10-28 `test-web.mjs` 결과는 `TEST-WEB: pass=94 fail=0` 입니다(390px·1280px, 오류 0, 외부 요청 0). `shot.mjs`는 한림 질문 해석과 노선 상세, 센터 모델 시험도 추가로 촬영합니다.

`shot.mjs`는 모든 촬영과 검증에 성공한 뒤에만 기획서가 쓰는 `assets/`의 화면 9개를 갱신합니다. 장면 6의 측정용 문장 표는 `demo-6-sentences-<폭>.png`에도 따로 남깁니다. 캡처를 갱신한 뒤에는 기획서 PDF를 다시 생성해야 합니다.
